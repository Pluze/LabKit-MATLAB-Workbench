# Changes

```labkit-page
id: changes
type: landing
audience: app-developer
summary: Trace accepted LabKit changes without reconstructing commits or pull requests.
```

Use a change record to understand why one accepted logical change happened, what changed for users and developers, and whether action was required. Records also own important alternatives and decision chains. They describe the net accepted result, not the order of commits or test runs used to deliver it.

## Choose A View

- Start from an App, library, or framework page to see changes affecting that component.
- Start from [GitHub Releases](https://github.com/Pluze/LabKit-MATLAB-Workbench/releases) to review one published LabKit version.
- Search by Change ID, component, workflow, or compatibility.

## Record Contract

Each record states why the change happened, what changed, its impact, and its compatibility or limits. When one accepted choice replaces another, the newer record names the Change IDs it supersedes. Stable Change IDs form the decision chain; filesystem paths do not act as compatibility identifiers.
